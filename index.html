HamUI

A UI framework for amateur radio software. One stylesheet covers layout and the everyday components; one dependency-free script adds the interactive radio instruments: spectrum, waterfall, meters and VFO. Dark by default with a light theme, and usable with a trackpad or touch screen.

Include

<link rel="stylesheet" href="dist/hamui.css">
<script src="dist/hamui.umd.cjs"></script>   <!-- window.HamUI -->
<script> HamUI.init(); </script>

Or as an ES module:

import 'hamui/css';
import HamUI, { Spectrum, Meter } from 'hamui';
HamUI.init();                       // set up every [data-ham] element on the page
const s = new Spectrum('#scope', { startHz: 14069500, spanHz: 12000 });
s.update(levels);                   // Float32Array of dB(m)

Like Bootstrap there are two ways to use it: add data-ham="..." attributes and call HamUI.init(), or construct a component class directly. Options can be passed as data-* attributes (for example data-min-db="-130") or as an object. Component events are bubbling ham:-prefixed CustomEvents.

Themes & tokens

Every color, font and spacing value is a --ham-* CSS custom property. Set data-theme="dark | light | auto" on <html> or on any container to switch themes; canvas components re-read their colors and repaint.

Waterfall color ramp --ham-wf-0 … --ham-wf-4
HamUI.theme.set('light');      // 'dark' | 'light' | 'auto'
HamUI.theme.toggle();
HamUI.theme.onChange(() => …);  // ham:themechange is also dispatched on document

Spacing follows a 4 px grid (--ham-space-1 … -7 = 4, 8, 12, 16, 24, 32, 48); radii are 4 / 6 / 8. The hit target --ham-hit is 30 px with a mouse and grows to 44 px on (pointer: coarse) devices.

Meters

Presets for an S-meter (dBm in; S9 = −73 dBm, or −93 dBm with data-vhf), power, SWR (non-linear scale) and ALC, plus custom scales. Peak hold is built in; use setOff() to dim the meters that don't apply when switching between receive and transmit.

const s = new HamUI.Meter('#s', { type: 's' });
s.set(-63);                 // "S9+10 -63"
pwr.setOff(true);           // dim while receiving

Spectrum

Feed it frames of dB values covering startHz … startHz + spanHz; it handles averaging, peak hold, the grid, the frequency axis, the passband and the dial line. A click emits a cancelable ham:tune event. The data below comes from the built-in SignalSimulator (20 m FT8 segment).

<div id="spec" data-ham="spectrum" data-start-hz="14069500" data-span-hz="12000"></div>

spec.setPassband(HamUI.passbandFor('USB', 2900));    // [100, 3000]
spec.setMarkers([{ hz: 14078000, color: 'warn', dashed: true, label: 'JS8' }]);
// other receivers on a shared SDR: passband relative to each marker's own dial

Waterfall

Each push() adds a row at the top. The color map follows the theme by default (theme); viridis, inferno, plasma, turbo and gray are built in, or pass an array of colors. autoLevel() sets the contrast from the history.

Colormap 
const wf = new HamUI.Waterfall('#wf', { startHz, spanHz, rows: 256, minDb: -125, maxDb: -75 });
wf.push(frame);
wf.setColormap('viridis');   // 'theme' | 'viridis' | 'inferno' | 'plasma' | 'turbo' | 'gray' | ['#000', '#0af', '#fff']
wf.autoLevel();

Panadapter

A spectrum above a waterfall sharing one FrequencyView, so zoom, pan and tuning always line up. HamUI.linkView(spectrum, waterfall) links any two components by hand.

Panadapter Click or drag to tune · drag the frequency scale or swipe sideways to pan · pinch to zoom · double-click to reset 12.0 kHz 
<div id="pan" data-ham="panadapter" data-start-hz="14069500" data-span-hz="12000"></div>

const pan = HamUI.getInstance('#pan');
pan.push(frame);                       // updates both views
pan.view.zoomAt(2, 14074000);          // zoom from code
pan.on('viewchange', e => …);          // {start, span, zoom}
pan.on('tune', e => …);                // {hz, source: 'click' | 'drag'}
pan.setDragTune('passband');           // 'press' (default) | 'passband' | 'always' | false

Channel strip

Give a spectrum a channels plan and it draws the channels in rows under the trace, on the same frequency view. Hover a channel to see its downlink, uplink and symbol rate. A click emits a cancelable ham:channel with the RX and TX frequencies, then highlights the channel and tunes the dial to it. A click never keys the transmitter. Dragging the strip pans, the same as dragging the frequency scale. Channels with a signal in them are drawn darker (occupancy: 'auto'). Keyboard: [ ] step through the channels in a row, ↑ ↓ change row.

const spec = new HamUI.Spectrum('#spec', {
  startHz: 10490e6, spanHz: 10e6,
  channels: HamUI.bandplans.qo100Wideband,     // or qo100Narrowband, or your own plan:
  // channels: {
  //   offsetHz: -8089.5e6,                    // TX = RX + offset, or txHz: (ch) => hz
  //   lanes: [{ label: '333 kS', sr: 333e3, from: 10492.75e6, to: 10499.25e6, step: 0.5e6 },
  //           { label: 'Custom', width: 25e3, slots: [145.5e6, { hz: 145.525e6, rxOnly: true }] }],
  //   fixed: [{ hz: 10491.5e6, width: 1.8e6, label: 'Beacon', rxOnly: true }],
  //   regions: [{ from: 10490.5e6, to: 10492.5e6, label: 'Beacon' }],
  //   select: 'rx+tx',                        // 'rx': clicks leave TX alone (txHz is null)
  //   occupancy: 'auto',                      // false, or (ch) => boolean
  // },
});
spec.on('channel', (e) => radio.set(e.detail));  // {rxHz, txHz, sr, width, label, lane, rxOnly, source}
spec.selectChannel(10494.75e6, { sr: 333e3 }); // highlight only: no event, no tune

Haptics

Frequency digits, knobs, segmented controls (including band and mode) and PTT ask for haptic feedback at each detent through HamUI.haptics. The built-in backend uses navigator.vibrate, which only Android browsers implement. Browsers cannot drive a laptop trackpad, so in a native shell route it to the platform instead, e.g. Tauri on macOS calling NSHapticFeedbackManager.

KindFired by
tickEach tuning step of a frequency digit; each knob step when the knob has few steps (≤ hapticSteps, default 32)
selectThe user picks another segment, band or mode
snapA knob is reset to its default (double-click)
edgeA frequency or knob reaches its min or max
pressPTT goes on or off
 
// Route feedback to a native shell (Tauri example)
HamUI.haptics.use((kind, detail) => window.__TAURI__.core.invoke('haptic', { kind }));

HamUI.haptics.enabled = false;   // turn it all off
HamUI.haptics.use(null);         // or silence the backend
HamUI.haptics.use();             // back to navigator.vibrate

// per component: data-haptics="false", or a knob's data-haptics="true" to tick on every step

Knob

Drag up and down, scroll, or use the arrow keys. Double-click returns to the default value. endless: true makes a VFO-style knob with no ends: the ring stays still, the pointer moves one detent per step, and every step emits ham:change with {delta, steps, value}. While you turn it, it shows how many steps this turn has made, then it goes back to showing the step size.

Band & mode

Band data lives in HamUI.bands (edges and the default FT8 frequency); passbandFor(mode, width) returns the passband relative to the dial.

DVB-S2 / DATV

Components for digital ATV receivers such as those used on the QO-100 wideband transponder. The DATV demo puts them together as a full receiver panel.

  • Constellation: I/Q symbols accumulate into a fading density map, with the ideal QPSK, 8PSK, 16APSK or 32APSK points overlaid. Pinch or ctrl+wheel to zoom.
  • MerMeter: red below the Es/N0 the MODCOD needs, amber just above it, green with margin. It also shows the decoding margin (D number).
  • LockStatus: the demodulator's progress, Search → Header → Demod → FEC → TS.
  • TrendChart: a rolling history of any reading, with threshold lines.

Video panel

A canvas for decoded video, with a title, a centred message, a stats overlay and a control bar underneath, so the controls never cover the picture. It never decodes: draw into vp.canvas with WebCodecs, WebGL or anything else. Muting puts the volume slider at 0 and remembers the level. When the browser holds sound back until a click, setSoundBlocked(true) shows a "Turn sound on" chip. Keys: M mute, F full screen; double-click the picture for full screen. The example plays a quiet test tone through AudioStreamPlayer.

const vp = new HamUI.VideoPanel('#video', { label: 'DATV video' });   // aspect: '16 / 9' | 'fill'
decoder.attach(vp.canvas);
vp.setTitle('N0CALL', 'H.265 · 1280×720 · 25 fps');
vp.setMessage('Waiting for a key frame', 'warn');   // '' | 'warn' | 'error'; null hides it
vp.setStats([['Video', '312 kbit/s'], ['Frames dropped', 3, 'warn']]);
vp.setLevel(audio.level());  vp.setTime(seconds);
vp.setSoundBlocked(audio.blocked);
vp.setAudioAvailable(false, 'No audio in this stream');   // disables mute and volume
vp.on('unmute', () => audio.start());                 // the "Turn sound on" chip
vp.on('volume', (e) => { audio.volume = e.detail.volume; audio.muted = e.detail.muted; });
vp.addButton({ label: 'Record', side: 'right', onclick });

Decode list

An FT8/FT4 receive log. Rows are grouped by cycle. CQ calls show in the accent colour, messages to myCall get an amber row, and your own transmissions are red. The bar under the header shows the position in the cycle, and turns red during your TX cycles (txPeriod). The list follows the newest decodes until you scroll up, then offers an "N new ↓" button. Click a row, or use ↑ ↓, to emit ham:select with the parsed message.

Streamed audio

hamui/media is a separate entry with no DOM components, so the UI bundle stays the same size. AudioStreamPlayer plays streamed PCM (DATV audio, SDR audio over a WebSocket) through an AudioWorklet ring buffer. A slow PI controller nudges the playback rate by at most 0.5 % to absorb the clock difference between sender and sound card. It stays within ±20 ms of the target at ±300 ppm over an hour. The target rises when arrival jitter grows, an underrun restarts at the target, and a burst beyond 3× the target drops the oldest audio in one step. Where the stream time skips ahead (frames lost on the way), the gap plays as silence, so the audio after it stays on time. The A/V sync classes (SyncCore, AudioClock, ArrivalClock, VideoQueue) are pure logic, driven by unit tests in simulated time. From the PlutoSAT station front end.

import { AudioStreamPlayer } from 'hamui/media';    // UMD: dist/hamui-media.umd.cjs, global HamUIMedia

const audio = new AudioStreamPlayer({
  target: 0.12,        // minimum buffer, s (0.04..1)
  startReserve: 0.25,  // buffer at least this until 3 s of arrivals are known (0: start at target)
  fillGaps: true, maxGap: 1,   // play gaps in ticks/time as silence, up to 1 s
});
button.onclick = () => audio.start();                  // browsers need a click or tap
ws.onmessage = (e) => audio.push(new Int16Array(e.data), { rate: 12000 });   // or Float32 planes, + ticks/time
// decoded or held audio: pass when it really arrived (performance.now() s), or arrival: false + noteArrival()
audio.push(planes, { rate: 48000, ticks, arrival: packetArrivedAt });
audio.noteArrival(ticks, performance.now() / 1000);
audio.volume = 0.7;  audio.muted = false;
audio.stats();      // {running, playing, fill, target, minTarget, jitter, ppm, underruns, drops, gaps, gapSeconds}
audio.level();      // 0..1 on a -60..0 dBFS scale, for a meter
audio.position();   // stream position being heard, 90 kHz ticks: the master clock for video
audio.flush();      // channel change: drop the buffer, prefill again
audio.setTarget(0.4);                     // minimum buffer 0.04..1 s (the target itself with adaptive: false)
analyserLevel(myAnalyserNode);            // the same meter scale for your own AnalyserNode
